What is Syrex?

Syrex is an end-to-end distribution management platform built for manufacturers and distributors who manage a network of trade outlets (dealers, retailers, service partners). It replaces spreadsheets, WhatsApp ordering, and disconnected ERPs with a single system that tracks every rupee and every unit — from the moment an order is placed to after-sales service and warranty resolution.

The platform has three access surfaces:

🖥️

Web Admin Dashboard

For internal teams — sales managers, warehouse staff, accounts, service managers. Full visibility and control over all operations.

📱

Sales Mobile App

For field sales agents. Place orders on the go, view order history, log outlet visits, and get real-time GPS tracked while in the field.

🔌

REST / tRPC API

For integration with existing ERP, billing, or reporting tools. Every function available through the UI is also available as an API.

Platform Modules

Syrex is built as a set of deeply integrated modules. Each module operates independently but shares data with the others — so a serial number from a dispatch automatically appears in the service module, and a payment automatically closes the correct invoice.

📋

Sales Orders

Create, approve, hold, or reject orders. Full approval workflow with audit trail. Priority levels. Multi-line orders with product catalogue.

📦

Dispatch & Logistics

Plan and execute dispatches from warehouse to outlet. Track transporter, vehicle, LR number. Partial dispatch support. Serial number capture.

🧾

Invoicing

Auto-generated on order approval. Configurable tax & charge rates (GST, freight, etc.). PDF export. Full invoice editing with recalculation.

💳

Payments & AR

Record outlet payments. Auto-allocate to oldest invoices. Track outstanding balances, AR aging reports, approval queues.

🏭

Warehouse & Inventory

Real-time stock levels per warehouse. Goods receipt. Stock adjustment with reason codes. Automatic deduction on dispatch.

🏪

Outlet Management

Maintain outlet master data. Link outlets to warehouses. Track outstanding balance, order history, contacts, and credit status.

🛠️

Service & Complaints

End-to-end complaint lifecycle. Assignment to field engineers. Visit logging. Test reports. Warranty decisions. Full activity audit.

🛡️

Warranty Management

Approve or reject warranty claims. Assign replacement serials. Auto-create fulfillment orders that flow through the standard dispatch pipeline.

📍

Field Sense (GPS Tracking)

Real-time GPS tracking of field agents. Live admin map. Auto shift management. Visit logging. Attendance & schedule reports.

📊

Reports & Analytics

Sales reports by outlet, period, product. AR aging. Dispatch summaries. Field visit counts. Shift attendance. All filterable and exportable.

🔐

Role-Based Access Control

Fine-grained permissions per module (read / write / manage / approve). Custom roles. Invitation-based onboarding. Audit log for every action.

📎

Product Catalogue

Manage brands, categories, and SKUs. Link products to prices. Products feed directly into order creation, dispatch, and service modules.

Order Status Reference

Each sales order passes through the following statuses. Every transition is recorded with the actor who made it and a timestamp.

Status Meaning Who triggers it What happens next
pending_approval Order just created, awaiting review Sales rep (web or mobile) Manager reviews and approves / holds / rejects
on_hold Paused — additional information needed Manager Can be approved or rejected once resolved
approved Approved — invoice auto-generated Manager (orders:approve permission) Enters dispatch queue
rejected Declined — reason recorded Manager Terminal state — no further action
partially_dispatched Some lines shipped, others pending System (auto on dispatch) Remaining lines can be dispatched in batches
fully_dispatched All ordered quantities shipped System (auto on final dispatch) Terminal state for the order
cancelled Order withdrawn Any authorised user (orders:manage) Cannot be cancelled once fully dispatched

Service Complaint Status Reference

Service complaints follow a strict linear workflow that cannot be skipped, ensuring proper documentation at every step.

Status Meaning Entry action
raised Complaint logged, not yet assigned Internal user creates complaint with serial numbers
assigned ASI / Service Engineer linked Manager assigns to field team
visit Field engineer is on site Engineer logs visit from mobile or web
test_result_submitted Engineer submitted test report & verdict Engineer submits structured test report
retest_requested First test inconclusive — another visit needed Manager requests retest
resolved Complaint closed — issue fixed or warranty decision made Tested OK close or warranty rejection
telephonic_closure Resolved over the phone without site visit Manager closes with mandatory reason note
cancelled Complaint withdrawn / duplicate Authorised user (service:cancel permission)

Role & Access Overview

Access is controlled through custom roles. Each role has a set of permissions per module. Below is the typical role mapping for a distribution company.

Role Primary access Typical user
Admin Full access to all modules (wildcard permission) Business owner, IT manager
Sales Manager Orders (read + write + approve), Outlets, Invoices, Reports Regional / zonal sales head
Sales Rep Orders (write own), Catalogue (read), Field Sense Field sales executive
Warehouse Manager Inventory (read + write), Dispatches (write), Outlets (read) Warehouse in-charge
Accounts Invoices, Payments, AR reports, Outlets (read) Finance / collections team
Service Manager Service complaints (manage + assign + approve + cancel) After-sales service head
Service Engineer Service complaints (read + write), Serial lookup Field service technician

Custom roles: Every permission can be toggled individually. You can create roles like "read-only auditor", "outlet-scoped sales rep" (sees only their outlet's data), or "dispatch-only warehouse assistant" to match your exact org structure.

Key Business Rules & Safeguards

Orders

An order cannot be created for an inactive outlet, or for an outlet with no assigned warehouse. Unit prices and quantities are locked at order creation time — they cannot be changed after the order is submitted.

Invoices

Invoices are auto-generated on approval and cannot be deleted. Tax rates applied at the time of invoice creation are stored immutably — a future rate change does not retroactively alter existing invoices. Charges can be manually adjusted by an authorised user (invoices:write permission).

Dispatch

A dispatch cannot exceed the remaining ordered quantity on any line. Stock is deducted atomically — if the warehouse has insufficient stock for even one line in a dispatch batch, the entire dispatch is rejected. Idempotency keys prevent duplicate dispatches from mobile or retry scenarios.

Payments

A payment amount must be greater than zero and must reference a valid outlet. Allocation is automatic (FIFO by invoice date) and cannot result in negative amounts due. The outlet's outstanding balance is always recalculated after every payment.

Service

Only internal users (not portal/outlet users) can raise complaints. The complaint workflow is strictly sequential — you cannot skip from "raised" to "test_result_submitted" without going through "assigned" and "visit". A serial number can only be used as a replacement serial in one complaint at a time.

Warranty Replacement

A warranty fulfillment order is created at zero value and skips invoice generation. It flows through the normal dispatch pipeline like any other order.

Data Integrity & Audit

Every significant action in the system is written to an immutable audit log: who did it, when, what changed, and what the previous state was. This covers order transitions, dispatch creation, payments, and all service complaint actions.

The service module additionally maintains a per-serial-number event ledger — every dispatch, complaint creation and replacement assignment is recorded against the serial number. This gives you a complete ownership and warranty history for any individual unit, traceable across all outlets.

Nothing is physically deleted. Orders, complaints, and invoices use status-based soft lifecycle management. Outlets and products use an isActive flag. Historical data is always available for reporting and audits.

Integration & Extensibility

Every feature in the platform is exposed as a typed API endpoint (tRPC over HTTP). This means any external system — existing ERP, custom reporting tool, third-party logistics tracker, or data warehouse — can read or write data through the same API the web dashboard uses.
